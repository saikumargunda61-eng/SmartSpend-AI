# Reusable recipe: Decider 2B tool selection

**Pattern tag:** `#tool-selection`

## Typed question

- Type: `choice`
- Instructions: choose the best next action for a student spending assistant
- Options:
  - `CHECK_BUDGET`
  - `CHECK_UPCOMING_EXPENSES`
  - `GIVE_SAVING_ADVICE`

## State supplied to Decider

- The user's natural-language request
- Available spending money in INR
- Upcoming essential expenses in INR

Only provide values entered by the user or generated by the application. Do not fabricate missing values.

## Wiring

`decision_pattern.choose_action(state)` sends a request to `/v1/systemone`, validates that the returned choice belongs to the declared option set, and returns the choice and confidence. `app.py` routes the choice to one deterministic tool. Below confidence `0.60`, the application uses a clarification fallback rather than running a tool selected with low confidence.

## Adaptation

1. Replace the options with your own tool names.
2. Rewrite the question instructions so each option has a clear, distinct meaning.
3. Keep option validation and a low-confidence fallback.
4. Evaluate against labelled examples before using the recipe in a real workflow.
5. Keep sensitive data out of state unless the deployment is designed and approved to process it.

This is an experimental reusable pattern, not a guarantee of safe decisions.
